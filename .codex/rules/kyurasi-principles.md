# Kyurasi 공통 개발 원칙

이 파일은 현재 프로젝트에 직접 적용되는 공통 원칙만 담는다. 새로운 작업 영역이 생기면 사용자가 제공한 원칙 중 관련 부분을 선택적으로 이 저장소에 구체화한다.

## 기본 태도

- 개발 난이도가 낮고 실패 원인을 분리할 수 있는 구조를 우선한다.
- 원칙은 실수의 영향을 줄이는 가드레일이다. 예외는 허용하지만 이유와 위험을 기록한다.
- 변경은 작고 되돌리기 쉽게 유지하며, 범위를 벗어난 정리 작업을 섞지 않는다.
- 사용자 데이터와 기존 파일을 보존하고, 파괴적 작업은 승인과 정확한 대상 확인 없이 실행하지 않는다.

## 타입과 경계

- TypeScript에서 `any`를 피한다. 외부 payload는 `unknown`으로 받고 runtime validation으로 좁힌다.
- 바뀔 수 있거나 여러 위치에서 쓰이는 event name, 상태값, 경로, 제한값은 상수 또는 config 한 곳에서 관리한다.
- 모듈의 책임과 의존성 방향을 단순하게 유지한다. hook 수집, 정규화, 상태 계산, 전송, 표현 계층을 섞지 않는다.
- 아직 반복되지 않은 코드를 성급하게 공통화하지 않는다.

## 상태와 멱등성

- 동일 hook event가 중복되거나 순서가 뒤바뀔 수 있다고 보고 상태 전이를 설계한다.
- 가능한 경우 안정적인 event identity를 사용하되, 공식 payload에 없는 식별자를 추측해 만들지 않는다.
- 상태명은 숫자 코드보다 의미가 드러나는 문자열을 사용한다.
- 시간 표현은 프로젝트 전체에서 UTC Unix timestamp milliseconds로 통일하고 이름에 단위를 드러낸다.

## 테스트

- 테스트는 실제 제품 코드 경로를 우회하지 않는다.
- parser·redaction·상태 계산은 작은 단위 테스트로, plugin wiring은 validation으로, 공식 앱 연동은 E2E로 구분한다.
- 성공 경로뿐 아니라 malformed input, 누락 필드, 중복 event, out-of-order event, 쓰기 실패를 검증한다.
- 테스트를 실행할 수 없으면 실행하지 못한 이유와 남은 위험을 기록한다.

## 협업

- 여러 독립 작업은 명확한 산출물과 파일 경계를 정해 작업자에게 나눈다.
- 팀장은 작업자 산출물의 가정을 교차 확인하고 통합 충돌을 해결한다.
- 최종 E2E QA와 합격 판단은 팀장이 직접 수행한다.
- QA 지적은 담당자에게 되돌리고, 수정 후 같은 흐름을 다시 검증한다.
